# 上流文書の取り込み

種別スキルの段階1。上流文書（`doc-chain.md` の表を参照）を読める状態にする。プロジェクトによって文書の置き場が違うため、次の順で試す。

## 手順

1. **ユーザーが場所を示していればそれに従う**。ファイルパスなら読む。URL なら手順3へ
2. **リポジトリ内を探す**。`docs/` 配下で文書種名（brief / prd / design / schedule / 調査）を含む Markdown を `Glob` で探し、見つかったら「これを上流として使うか」を確認する
3. **外部ツール（Confluence / Notion / Google Docs）の場合**、直接は読めない。次のどちらかを依頼する:
   - Markdown（またはプレーンテキスト）でエクスポートしたものを貼り付けてもらう
   - ローカルにファイルとして保存してもらい、パスを教えてもらう
   依頼文の例: 「PRD が Confluence にあるなら、ページを Markdown でエクスポートして貼ってください。見出しと本文だけで十分です」
4. **上流が無い場合**は無いことを文書の冒頭（関連文書の欄）に「Brief: なし」のように明記し、前提質問で補う。上流の作成を促してもよいが、作成を強制しない

## 取り込んだ後

- 上流文書へのリンク（パスまたは URL）を、生成する文書の冒頭「関連文書」に載せる
- 上流の未決事項をそのまま引き継ぐ。解決していない論点を勝手に確定させない
- 上流に書かれた事実と、自分の推測を区別して書く（`/dev-docs:tech-writing` の「事実と意見の書き分け」）
