# 自己レビュー

書き終えたら、次のパスを順に回す。修正を受けたあとは、目的パスから回し直す。小さな修正では、直した箇所にだけパスを当て、ほかの箇所で見つけた問題は返答で指摘するだけにする（突き合わせパスだけは文書全体で回す）。既存の文書のレビューを頼まれたときも、このパスで指摘を作る。指摘は「どこが・なぜ問題で・どう直すか」をセットで返す。

規則の中身は `${CLAUDE_PLUGIN_ROOT}/references/writing.md` にある。パスはそれを確かめる観点の並び。

## 目的パス

「この文書は誰が読んで、何を判断・実行するためのものか」を 1 文で言い、各節がそれに効いているかを問い直す。効いていない節は、文面を直す前に差し替えるか削る。書かないと決めたこと（個人用ナレッジの書式、作業用のメモ、AI との会話の経緯）が混ざっていないかも確かめる。問い直した結論は返答に添える。

## 見出しパス

見出しだけを上から読む。それだけで問いへの答えまで論旨がたどれるか。見出しがメッセージ型か。疑問形・呼びかけ・比喩・「はじめに」「まとめ」が無いか。会社テンプレートの見出しを書き換えていないか（「見出し」）。

## 冒頭パス

冒頭の数行だけを読む。結論・理由の要点・読者に求めることが入っているか。経緯から始まっていないか（「構成」）。

## 用語パス

用語集・上流文書・合意フェーズで決めた語と一致しているか。造語、比喩、言い換えが無いか。同じ概念を別の語で呼んでいないか。初めて出る語に定義があるか（「用語」）。

## 参照パス

ID を振って ID で参照していないか。「後述」を前提に読ませていないか。後ろの節を読まないと分からない箇所が無いか（「参照」）。

## 冗長パス

全文を読み、削って意味が変わらない語・文・段落を削る（「文」）。

## AI 臭パス

「AI 臭さ」の 6 つと照合し、該当箇所を書き直す。

## 出典パス

調べた事実を含む文書すべてで回す。「根拠:」「出典:」をすべて拾い、区分名だけで URL・`path:line`・ページ ID が無いものを直す。一次情報に当たったか。断定している事実に根拠が無ければ、根拠を付けるか「出典未確認」を付ける（`${CLAUDE_PLUGIN_ROOT}/references/citation-rules.md`）。

## 突き合わせパス

調査記録があるときに回す（`${CLAUDE_PLUGIN_ROOT}/references/research-record.md`）。

- 文書に書いた事実が、すべて調査記録までたどれるか。言い換えの途中で、出典の無い断定が紛れ込んでいないか
- 調査記録で `【結論の根拠】` が付いた事実が、文書から抜けていないか。抜けていたら黙って書き戻さず、「次の事実が文書から落ちた」と返答で報告し、戻すかを利用者に聞く

## 種別パス

種別の reference（`types/<id>.md`）の「必須の情報」が、文書の中に具体的に書かれているか。「性能を考慮する」のような具体値の無い記述は、欠けとみなす。欠けは削らず「未決事項」に判断者つきで載せる。
