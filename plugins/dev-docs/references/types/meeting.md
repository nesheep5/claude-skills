# 打ち合わせ資料

この文書が答える問い: この打ち合わせで、何を決め、何を聞くか。

打ち合わせの前に参加者へ渡す資料。叩き台、アジェンダ、相手に聞く質問事項を含む。打ち合わせの時間を、前提の説明ではなく判断と質疑に使えるようにするためにある。使いながら育てる種別なので、ここには最小限だけを置く。

## 前提質問

- 打ち合わせの相手は誰か。社内か社外か。相手は何を知っていて、何を知らないか
- この打ち合わせで決めたいこと、聞きたいことは何か
- 時間はどれだけあるか

## 必須の情報

- **決めること・聞くこと**: 打ち合わせの終わりに何が決まっていればよいか。冒頭に置く
- **参加者が事前に知っておくこと**: 判断や回答に要る前提。相手が既に知っていることは書かない
- **論点ごとの叩き台**: こちらの案と、その理由。相手が「はい / いいえ / ここを変えて」で応えられる形にする
- **相手に聞く質問**: 1 問ずつ、なぜ聞くか（答えで何が変わるか）を添える。答えやすい順ではなく、判断への影響が大きい順に並べる

## たたき台の目次

合意フェーズで組み替える出発点。見出しの既定はラベル型（`writing.md` の「見出しの型は読者の読み方で選ぶ」）で、各節の結論は節の最初の 1 文で言い切る。読者が通読して判断する文書に寄せるときは、「最初の 1 文」の例をそのまま見出しにしてメッセージ型にしてよい。

```markdown
# <打ち合わせ名> 資料
- 日時 / 参加者 / 作成者

<冒頭の要約: この打ち合わせで決めること・聞くことを 3〜5 行>

## 決めたいこと
  最初の 1 文: 決めたいことを言い切る（例: 今日決めたいのは移行の対象範囲）
## 前提
  最初の 1 文: 前提を言い切る（例: 旧版のサポートは来月末で終わり、延長は無い）
## 論点 1: <論点の名前>
  最初の 1 文: 叩き台を言い切る（例: 移すのは今使っている 3 機能だけで足りると考えている）
## 論点 2: <論点の名前>
## 聞きたいこと
  - <質問> — <なぜ聞くか>
```

## 下流に渡すもの

打ち合わせのあとに、決まったこと・保留になったこと・次の行動（誰が・いつまでに）を残す。議事録や上流の文書（Brief・検討資料）に反映する。
