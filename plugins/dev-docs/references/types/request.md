# 依頼書

この文書が答える問い: 誰に、何を、どの状態になるまでやってほしいか。

他の人やチームに作業を渡すための文書。受け手が、依頼者に聞き返さずに着手し、終わったと判断できるようにするためにある。使いながら育てる種別なので、ここには最小限だけを置く。

## 前提質問

- 受け手は誰か。その人は背景をどこまで知っているか
- 終わったと言える状態は何か
- 期限と、他の作業に対する優先度は

## 必須の情報

- **渡す作業と完了の状態**: 何をやれば終わりか。確かめられる状態で書く（「〜の一覧が共有のページにあり、各項目に判定が付いている」）。冒頭に置く
- **背景**: なぜ頼むか。受け手が判断に迷ったときの拠り所になる分だけ書く
- **期限と優先度**: いつまでに。他の作業と比べてどれだけ急ぐか
- **任せる範囲と相談してほしい範囲**: 受け手が自分で決めてよいこと、決める前に相談してほしいこと
- **参照先**: 必要な資料・コード・連絡先

## たたき台の目次

合意フェーズで組み替える出発点。見出しは、その節の結論を言い切る文に置き換える。

```markdown
# <作業名> 依頼
- 依頼者 / 受け手 / 期限

<冒頭の要約: 何を、どの状態まで、いつまでに。3〜5 行>

## <完了の状態を言い切る（例: 対象ライブラリ 5 つそれぞれに、移行の可否が判定されている）>
## <背景を言い切る（例: 来期のランタイム更新の前に、止まる箇所を知りたい）>
## <任せる範囲を言い切る（例: 調べ方は任せる。可否の基準を変えるときは相談してほしい）>
## 参照先
```

## 下流に渡すもの

受け手に渡す: 完了の状態。受け手が完了を報告するときは、この状態と突き合わせる。
