# 指摘の取り込み

セッション中に書き方の指摘を受けたら、文書を直すのと同時に、その指摘をローカルルールに取り込む。使うほど利用者の好みに沿った文書が出るようにするため。置き場の U と P は `${CLAUDE_PLUGIN_ROOT}/references/local-rules.md` のとおり。

## 振り分け

指摘を次の 4 つのどれかに振り分ける。

- **この文書だけの話**（「この節は削って」「ここは 3 行で」）: 取り込まない
- **利用者の好み**（「要件に ID を振らないで」「表は使わないで」）: `U/style.md` に追記する
- **ドメインの語**（「その言い方ではなく『〜』と呼んでいる」）: `U/glossary.md` の、作業中のプロジェクト（リポジトリのディレクトリ名）の節に追記する。節が無ければ作る
- **誰にでも効く一般則**（どの利用者・どの文書でも成り立つ書き方の規則）: `U/promote-candidates.md` に追記する。プラグイン本体には書き込まない

迷ったら「この文書だけの話」として扱う。取り込みすぎた好みは、後の文書を誤った方向へ曲げるため。

## 書式

`style.md` と `promote-candidates.md`:

```markdown
## <規則を 1 文で>
- なぜ: <理由>
- 例: <指摘を受けた場面と、直す前 → 直した後>
- 追加日: YYYY-MM-DD
```

`glossary.md`:

```markdown
## <プロジェクト名>
- **<語>**: <意味>。使わない言い方: <言い換え>（追加日: YYYY-MM-DD）
```

例を必ず書く。規則だけだと、後で読み返したときに誤って広げて当てはめやすい。

## 書き込む前に

- 既存の項目と重なるなら、新しい項目を足さずに既存の項目を直して統合する
- 既存の項目と矛盾するなら、書き込まずに利用者に聞く
- `style.md` の項目が 30 を超えたら、統合の整理を提案する

## 知らせ方

確認を挟まずに書き込み、返答の末尾に 1 行で知らせる。

- 好み: `好みに追加: <規則>`
- 語: `用語に追加: <語>`
- 一般則: `本体の候補に追加: <規則>`

利用者が「それは今回だけ」と言ったら、その項目を消す。

SKILL.md の「置き場の解決」で U がプラグインのデータディレクトリになったとき（設定 `local_rules_dir` が未設定のとき）は、最初の書き込みで次を 1 回だけ伝える。伝えたら `U/.notified` を作り、以後はこのファイルの有無で判定する。

> ローカルルールをプラグインのデータディレクトリに書きました。設定 `local_rules_dir` でディレクトリを指定すると、アンインストールしても残ります。

## チームの用語集

P に `glossary.md` があるとき、ドメインの語を U に書いたあとで「チームの用語集にも載せますか」と聞く。了承を得たら P の `glossary.md` にも同じ書式で書く。
