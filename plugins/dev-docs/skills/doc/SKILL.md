# 開発の文書を書く

開発にまつわる文書を、読者が冒頭で判断に要ることを受け取れ、見出しだけで論旨がたどれ、書いた事実を後から確かめられる形で書く。種別ごとの決まった構成に当てはめるのではなく、文書ごとに読者と目次を合意してから書く。

## 置き場の解決

references の中のパスは、プラグインのルート ${CLAUDE_PLUGIN_ROOT} からの相対で読む。references に出てくる U と P は次の場所を指す。

- U（利用者のローカル）: `${user_config.local_rules_dir}`。この値が空か、`${user_config.` のまま展開されていないときは `${CLAUDE_PLUGIN_DATA}`
- P（プロジェクトのローカル）: 作業中のプロジェクトのルートにある `.claude/dev-docs/`

## 流れ

### 1. 依頼を見極める

- 新規作成 / 大きな改稿 / 小さな修正 / レビューのどれかを判定する。見出しの構成か順序が変わるなら大きな改稿、変わらないなら小さな修正とする
- これとは別に、表現だけの修正か、中身（事実）の修正かを見分ける。大きな改稿にも小さな修正にも当てる
- 文書の種別を判定する。種別の id は `brief`（なぜやるか）・`prd`（何を提供するか）・`design-doc`（どう作るか）・`dev-schedule`（いつ何を出すか）・`research`（調査をもとに何を選ぶか）・`meeting`（打ち合わせで何を決め何を聞くか）・`request`（誰に何を頼むか）。どれにも当たらない文書は、共通ルールだけで書く。迷ったら候補を 1 つ挙げ、合意フェーズの「読者と目的」で確かめる
- `${CLAUDE_PLUGIN_ROOT}/references/local-rules.md` に従ってローカルルールを読み、種別の reference（`references/types/<id>.md`、ローカルにあればそちら）を読む
- 共通ルール `${CLAUDE_PLUGIN_ROOT}/references/writing.md` を読む
- 上流の文書があれば `${CLAUDE_PLUGIN_ROOT}/references/source-intake.md` に従って取り込む

### 2. 調べる（調べることがあるときだけ）

一次情報に当たり、結果を調査記録に書く（`${CLAUDE_PLUGIN_ROOT}/references/research-record.md`、出典の書き方は `${CLAUDE_PLUGIN_ROOT}/references/citation-rules.md`）。表現だけの修正では調べ直さず、調査記録にも触れない。

### 3. 合意する（新規作成と大きな改稿だけ）

読者と目的・答える問い・目次・用語の 4 項目を 1 つのメッセージで示し、利用者の了承を得てから本文に進む（`${CLAUDE_PLUGIN_ROOT}/references/agreement.md`）。小さな修正とレビューでは省く。

### 4. 書く

調査記録から書き起こす。文書の側で新しい事実を足さない。小さな修正では、頼まれた箇所以外を書き換えない。直した箇所には共通ルールを当てる。

### 5. 自己レビューする

`${CLAUDE_PLUGIN_ROOT}/references/review.md` のパスを順に回す。既存の文書のレビューを頼まれたときは、このパスと次の下流チェックだけを回し、指摘を返す。

小さな修正では、パスを直した箇所にだけ当てる。ほかの箇所で見つけた問題は直さず、返答で指摘するだけにする。ただし突き合わせパスは文書全体で回す。表現の修正で事実が落ちたことに気づくためだ。

### 6. 下流チェック

次の文書に渡す情報が具体的に書かれているかを確かめる（`${CLAUDE_PLUGIN_ROOT}/references/doc-chain.md` と、種別の reference の「下流に渡すもの」）。欠けは削らず、未決事項に判断者つきで載せる。

## 出力先

次の優先順で決め、書いた場所を返答で必ず伝える。調査記録は文書の隣に `<文書名>.research.md` で置く（ローカルルールで変えられる）。

1. 依頼で示された場所
2. 既存の文書の修正なら、その文書の場所
3. ローカルルール（`style.md`）で指定した置き場
4. プロジェクトの慣習（`docs/` の下に同じ種別の文書があるなど）
5. どれにも当たらなければ `docs/<id>/YYYY-MM-DD-<テーマ>.md`

ツール専用の隠しディレクトリや、リポジトリの外は既定にしない。

## 指摘を受けたら

文書を直すのと同時に、`${CLAUDE_PLUGIN_ROOT}/references/learning.md` に従って指摘を振り分け、U に取り込む。返答の末尾で取り込んだことを 1 行で知らせる。

## 持ち込まないもの

他人に渡す文書に、個人用ナレッジの書式（「学び」「未解決の論点」のような節）、作業用のメモ、AI との会話の経緯を持ち込まない。
